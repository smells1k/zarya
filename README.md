# Заря OS

**Текущий статус:** в репозитории находятся исходники и конвейер сборки; готового ISO в дереве исходников нет. ISO появится как отдельный файл GitHub Release только после успешного прохождения workflow `Build and publish Zarya OS`. До этой проверки не считайте образ собранным или загрузочным.

Заря — Debian trixie live-система с собственной графической оболочкой, которая рисует прямо в Linux framebuffer. Для запуска Windows-программ используется Wine с отдельной полноэкранной X11-сессией на framebuffer.

## Получить ISO

Откройте [страницу Releases](https://github.com/smells1k/zarya/releases) и скачайте `zarya-os-<версия>-amd64.iso` и соответствующий `.sha256`. ISO не хранится в git и не должен собираться в каталоге исходников: сборочный rootfs и промежуточные файлы помещаются в системный временный каталог, а GitHub Release публикует ISO и OTA-пакет отдельными файлами.

В GitHub Actions release workflow запускается для тега вида `v1.0.2`. Он собирает гибридный BIOS/UEFI ISO и checksums, затем публикует их с `GITHUB_TOKEN` и разрешением `contents: write`. Подписанный OTA-пакет добавляется в тот же Release, если настроен ключ подписи; без ключа Release всё равно содержит ISO, но OTA-asset будет пропущен.

Для OTA владелец репозитория должен один раз добавить GitHub Actions secret `ZARYA_OTA_SIGNING_KEY` — содержимое соответствующего приватного PEM-ключа. Публичный ключ, встроенный в систему, находится в `packaging/ota/ota-public.pem`. Приватный ключ не входит в репозиторий; не коммитьте его и не публикуйте в логе workflow. Workflow намеренно не создаёт неподписанное OTA-обновление.

## Запуск и установка

1. Запишите ISO на USB и загрузите компьютер с него. В live-сессии изменения теряются после выключения.
2. Для постоянной установки нужен диск **не меньше 32 GiB**. Откройте терминал и сначала внимательно проверьте устройство:

   ```bash
   lsblk
   sudo zarya-install /dev/sdX
   ```

   Замените `/dev/sdX` на весь целевой диск, например `/dev/sdb` или `/dev/nvme0n1`, а не раздел `...1`. Инсталлятор уничтожит все данные выбранного диска. При подтверждении нужно ввести `ERASE <путь-к-диску>`; флаг `--yes` отключает это подтверждение.

   Разметка: BIOS boot 2 MiB, EFI 512 MiB, система A 8 GiB, система B 8 GiB, оставшееся место — постоянный раздел `/home`. GRUB хранит счётчик пробных загрузок в EFI-разделе. На новый слот переключаются только после полной записи образа.

3. После сообщения об успешной установке перезагрузитесь и выньте USB. Пользовательские файлы находятся на отдельном разделе и сохраняются при обновлении системы.

Инсталлятор пока запускается из терминала; графического мастера установки нет. На целевом диске создаются разделы заново, поэтому перед запуском сделайте резервную копию.

### Учётные записи

В текущем live-образе заданы `zarya` / `zarya` и `root` / `zarya`; для `zarya` включён sudo без пароля и автоматический вход в графическую сессию. Это демонстрационные значения, а не безопасная конфигурация для недоверенной сети. Измените пароли после установки и не включайте удалённый доступ без отдельной настройки.

## Обновления без перезаписи флешки

OTA работает только после установки на диск с разделами `ZARYA_A`, `ZARYA_B`, `ZARYA_DATA` и `ZARYA_EFI`. Live-режим с ISO/USB не обновляет сам себя.

```bash
zarya-update status
zarya-update check
sudo zarya-update update
# или скачать указанную версию и сразу перезагрузиться:
sudo zarya-update update 1.0.2 --reboot
```

Обновление скачивается из GitHub Release, проверяются подпись manifest и SHA-256 корневого образа, после чего неактивный слот полностью перезаписывается. Данные `/home` остаются отдельно. GRUB делает до трёх пробных запусков; система помечает слот успешным после инициализации framebuffer-оболочки. Если система не дошла до оболочки, watchdog инициирует перезапуск, а GRUB возвращается к предыдущему слоту. Для ручной установки проверенного `.zup`-файла:

```bash
sudo zarya-update install /путь/к/zarya-os-1.0.2-amd64.zup
```

Обновления должны быть выпущены тем же ключом, публичная часть которого уже встроена в установленную систему. Ротация ключа требует отдельного доверенного механизма и сейчас автоматически не выполняется.

## Wine

Wine включён в сборку. Двойной щелчок по `.exe` в приложении «Файлы» завершает оболочку и запускает программу в отдельной X11-сессии на `/dev/fb0`; после закрытия Wine оболочка запускается снова. Если Wine не установлен в пользовательской сборке, доступна команда `sudo zarya-wine install`.

Совместимость зависит от конкретной Windows-программы, графического драйвера и доступной памяти. Wine не является Windows и не гарантирует запуск всех приложений.

## Сборка

Требуется Debian/Ubuntu с root-доступом, сетью и пакетами `debootstrap`, `squashfs-tools`, `xorriso`, `grub-pc-bin`, `grub-efi-amd64-bin`, `grub-common`, `mtools`, `dosfstools` и `cpio`. Пример для Debian/Ubuntu:

```bash
sudo apt-get update
sudo apt-get install debootstrap squashfs-tools xorriso grub-pc-bin \
  grub-efi-amd64-bin grub-common mtools dosfstools cpio ca-certificates zstd
sudo env ZARYA_VERSION=1.0.2 \
  ZARYA_WORKDIR=/var/tmp/zarya-build \
  ZARYA_OUT=/var/tmp/zarya-os-1.0.2-amd64.iso \
  bash packaging/build-iso.sh
```

Зависимости самого образа (включая ядро, Wine и инструменты установки) конвейер устанавливает внутри временного Debian rootfs. Локальная сборка ресурсоёмкая; не задавайте workspace каталог как `ZARYA_WORKDIR` и не складывайте ISO в git-дерево.

Проверки синтаксиса скриптов, компиляции Python и обработки событий ввода выполняются workflow `Validate source`. Проверка `v1.0.1` в VMware выявила проблему с клавиатурой/мышью; исправление выпускается как `v1.0.2`. Успешная CI-сборка сама по себе не подтверждает запуск на целевой машине, установку на диск или применение OTA.
