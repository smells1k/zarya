# Заря OS

**Текущий статус:** исходники переводятся с Debian и оболочки Zarya на Ubuntu 26.04 LTS с полным рабочим столом Kubuntu/KDE Plasma. ISO 2.0.0 не считается проверенным релизом до успешной публикации и практического запуска в VMware с работающими перемещением указателя и щелчками. Образ публикуется отдельно и не хранится в git.

Пользователь проверил старый Debian-образ v1.0.4 и сообщил, что мышь в нём не работает. Новый вариант убирает самодельный framebuffer-рабочий стол: используется стандартная Plasma Wayland-сессия Kubuntu, системный ввод через libinput и обычный графический стек Ubuntu. Это изменение реализации, **а не подтверждение, что мышь уже работает**. Критерий проверки — именно собранный ISO, запущенный в VMware с работающими перемещением указателя и щелчками.

## Состав системы

- Основа: **Ubuntu 26.04 LTS (Resolute Raccoon)**, компоненты `main`, `restricted`, `universe` и `multiverse`.
- Рабочий стол: пакет **`kubuntu-desktop`** с обычными рекомендуемыми компонентами Kubuntu; Plasma Wayland — стандартная сессия, вход выполняет SDDM.
- Образ также содержит ядро Ubuntu generic, live-загрузчик, VMware Open VM Tools, драйвер VMware-видео и libinput, инструменты установки и подписанного A/B-обновления, а также Wine.
- Оболочка Zarya больше не запускается вместо KDE. Windows-программы можно запускать командой `zarya-wine /путь/к/программе.exe`; в Plasma используется XWayland.

## Получить ISO

После публикации откройте [страницу Releases](https://github.com/smells1k/zarya/releases) и скачайте все части `zarya-os-<версия>-amd64.iso.partNN`, соответствующий `.iso.sha256`, `JOIN_ISO.txt` и `SHA256SUMS`. GitHub ограничивает размер одного release asset, поэтому ISO разбит на части. В Linux/macOS соедините их в исходном порядке и проверьте образ:

```bash
cat zarya-os-<версия>-amd64.iso.part* > zarya-os-<версия>-amd64.iso
sha256sum -c zarya-os-<версия>-amd64.iso.sha256
```

GitHub Actions собирает и публикует ISO для тега вида `v2.0.0`; подписанный OTA-пакет публикуется дополнительно, только если в настройках репозитория задан secret `ZARYA_OTA_SIGNING_KEY`.

Публичный OTA-ключ встроен в `packaging/ota/ota-public.pem`. Приватный ключ хранится только в GitHub Actions secret; его нельзя коммитить или выводить в лог. Без ключа workflow может опубликовать ISO, но не OTA-пакет.

## Запуск и постоянная установка

1. Запишите ISO на USB и загрузите компьютер. Live-сессия автоматически входит под пользователем `zarya` в KDE Plasma; изменения live-сессии пропадут после выключения.
2. Для постоянной установки нужен целый диск **не меньше 64 GiB**. В Plasma откройте Konsole, проверьте устройства и внимательно выберите целевой диск:

   ```bash
   lsblk
   sudo zarya-install /dev/sdX
   ```

   Укажите устройство целого диска, например `/dev/sdb` или `/dev/nvme0n1`, а не раздел `...1`. Установщик полностью стирает выбранный диск. Для подтверждения введите `ERASE <путь-к-диску>`; параметр `--yes` отключает подтверждение.

   Разметка: BIOS boot 2 MiB, EFI 512 MiB, системные слоты A и B по **20 GiB**, остаток — постоянный раздел `/home`. Обновление сначала записывается в неактивный слот; Plasma подтверждает его после запуска KWin и `plasmashell`. При неудачном старте A/B-механизм возвращается к предыдущему слоту.

3. После сообщения об успешной установке перезагрузитесь и выньте USB. Пользовательские файлы хранятся на отдельном разделе и не стираются при OTA-обновлении.

Установщик пока запускается из Konsole, графического мастера нет. Перед установкой сделайте резервную копию: разметка целевого диска создаётся заново.

### Учётные записи и безопасность

В образе заданы `zarya` / `zarya` и `root` / `zarya`; для `zarya` включены автоматический вход в Plasma и sudo без пароля. Это демонстрационные значения, а не безопасная конфигурация для недоверенной сети. Измените пароли после установки и не включайте удалённый доступ без отдельной настройки.

## Переход со старой версии

Переход с Debian/Zarya v1.x на Kubuntu — **смена базовой системы и разметки**, а не обычное OTA-обновление. Старые установки с разделами A/B по 8 GiB не совместимы с новым полным рабочим столом и новым форматом обновлений. Для перехода нужно сохранить резервную копию пользовательских файлов, загрузить новый ISO и выполнить чистую установку на диск не меньше 64 GiB. Установщик уничтожит выбранный диск; заранее скопируйте нужные данные на другой носитель.

Новые OTA-пакеты предназначены только для установленной Zarya OS на Ubuntu 26.04 LTS с разделами `ZARYA_A`, `ZARYA_B`, `ZARYA_DATA` и `ZARYA_EFI`. Live-режим с ISO/USB не обновляет сам себя.

```bash
zarya-update status
zarya-update check
sudo zarya-update update
# или установить указанную версию и сразу перезагрузиться:
sudo zarya-update update 2.0.0 --reboot
```

Подпись manifest и SHA-256 содержимого проверяются до изменения неактивного слота. GRUB делает до трёх пробных запусков. Слот подтверждается только после запуска Plasma; если рабочий стол не поднялся, watchdog инициирует перезапуск и GRUB возвращается к предыдущей системе. Для ручной установки проверенного `.zup`:

```bash
sudo zarya-update install /путь/к/zarya-os-2.0.0-amd64.zup
```

OTA-пакет должен быть подписан тем же ключом, чей публичный ключ встроен в установленную систему. Автоматической ротации ключа нет.

## Wine

Wine и 32-битные зависимости включены в образ. Из Konsole в Plasma можно запустить:

```bash
zarya-wine /путь/к/программе.exe
```

Если Wine отсутствует в пользовательской сборке, установите его командой `sudo zarya-wine install`. Совместимость зависит от Windows-программы и доступных ресурсов; Wine не гарантирует запуск всех приложений.

## Сборка

Для сборки рекомендована Ubuntu 26.04 с root-доступом, сетью и пакетами `debootstrap`, `ubuntu-keyring`, `squashfs-tools`, `xorriso`, `grub-pc-bin`, `grub-efi-amd64-bin`, `grub-common`, `mtools`, `dosfstools`, `cpio`, `ca-certificates`, `zstd` и `openssl`. Полный Kubuntu загружает много пакетов; оставьте не менее 30 GiB свободного места во временной файловой системе.

```bash
sudo apt-get update
sudo apt-get install debootstrap ubuntu-keyring squashfs-tools xorriso \
  grub-pc-bin grub-efi-amd64-bin grub-common mtools dosfstools cpio \
  ca-certificates zstd openssl
sudo env ZARYA_VERSION=2.0.0 \
  ZARYA_WORKDIR=/var/tmp/zarya-build \
  ZARYA_OUT=/var/tmp/zarya-os-2.0.0-amd64.iso \
  bash packaging/build-iso.sh
```

Сборщик устанавливает `kubuntu-desktop` вместе с рекомендуемыми пакетами в отдельный Ubuntu rootfs; файлы сборки остаются вне каталога исходников. Workflow `Build and publish Zarya OS` выполняется на Ubuntu 26.04.

## Проверки и статус мыши

Синтаксис упаковочных скриптов, GRUB-конфигурации, Python-код и unit-тесты проверяются workflow `Validate source`. До миграции VMware-проверка v1.0.4 уже показала отсутствие мыши. Обработка событий ввода в сохранённых файлах `shell/input.py` и `tests/test_input.py` сама по себе проблему в том ISO не исправила, а новая Plasma-сборка ещё не проверена. Поэтому **не считать работу мыши исправленной**, пока фактический ISO Kubuntu 26.04 не загружен в VMware и не проверены движение и нажатия мыши.
